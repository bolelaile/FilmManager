> **与方案的偏差（务实取舍）**：
> 1. **BMP 输出**：Sharp/libvips 不支持 BMP 写出，方案中 `sharp.format.bmp` 不可用。改为通过 `.raw()` 取 RGB 像素后用纯 JS 24bpp BMP 编码器（`encodeBmp24`，bottom-up BGR、行 4 字节对齐）自行编码。
> 2. **16-bit TIFF**：sharp 的 `tiff({ bitdepth })` 仅接受调色板位深（1/2/4/8），16-bit 改由管道 `toColorspace('rgb16')` 决定输出位深，不传 bitdepth 选项。
> 3. **批量并发**：方案提及复用 worker-pool 子线程；实现采用主进程 async 并发限流池（并发 = min(4, cpu-2)），因 Sharp 操作本身异步（libvips 线程池）且不阻塞事件循环，更简单且内存可控；取消通过标志位实现。
> 4. **字体**：首期使用系统字体（Windows 优先微软雅黑），内嵌字体子集列为后续优化（方案 §4.5 / §16）。
>
> **v1.3.6 修复轮次（预览/齿孔/背景/位深/流程）**：
> 1. **齿孔不显示**：原实现用"在实色边框上画透明矩形"挖孔，透明矩形是 no-op，齿孔被实色边框覆盖。改为 SVG `<mask>`——边框条为白(可见)、齿孔为黑(挖空)，齿孔处真正透明，露出下层背景/图像。边字置于齿孔两组之间的中央留白区，避免与齿孔重叠。
> 2. **背景不可见**：是齿孔 bug 的连锁后果——实色边框盖住背景。齿孔挖通后，纯色/高斯模糊背景即通过齿孔与留白区透出，切换背景可见。背景层填充整个画布，边框经 mask 叠加于上，孔位与留白透出背景。
> 3. **位深**：预编译 libvips **不支持原生 10/12-bit**（无 AVIF、`raw()` 强制返回 8-bit 无法做位深量化、tiff bitdepth 仅 1/2/4/8）。UI 提供 8/10/12/16-bit 四档；10/12/16-bit 统一在编码末端 `toColorspace('rgb16')` 输出为 16-bit 容器（PNG/TIFF/WebP），10/12-bit 标注"以 16-bit 容器存储"。JPEG/BMP 仅 8-bit。
> 4. **16-bit 输出路径修正**：原在管道中途对图像 `toColorspace('rgb16')` 再合成到 8-bit 画布会丢失位深；改为全程 8-bit 合成，仅在末端编码前 `toColorspace('rgb16')`，已验证输出 PNG depth=ushort。
> 5. **尺寸上限**：长边硬上限与输入框 max 由 8000 提升至 **16384**；默认 longEdge 由 2048 提升至 4096。
> 6. **导出流程**：① 单张导出走 `await render`，不依赖 `done` 事件（原单张不发 done 导致 onDone 永不触发、按钮/进度条卡死）；单张仅按钮 loading、不弹进度条、成功后关闭弹窗。② 批量导出保留进度条 + 可靠取消（标志位），成功后关闭弹窗并隐藏进度条，取消则保留弹窗便于重试。③ 预览解码缓存（按 photoId+rotation 缓存解码后的预览图，配置变更不再重复 RAW 解码）+ stale 丢弃（仅展示最新一次预览请求，避免乱序覆盖）。
>
> **v1.3.6 修复轮次 2（纯黑/全模糊/投影/布局）**：
> 7. **纯色导出全黑 / 高斯模糊整图模糊（根因）**：sharp 的链式 `.composite([A]).composite([B])` **不会累积**——第二次调用覆盖第一次，导致图像层丢失，只剩背景层（纯色=黑、模糊=整图模糊）。改为**单次 `.composite([...])` 调用**按 z 序传入全部图层（投影→图像→边框）。已用像素采样验证两种背景下中心均为锐利照片。
> 8. **图层重构（满足"原图+边框居中、背景填充、投影分离"）**：① 引入"胶片块"(film block) 概念——照片+边框组成一块，居中放置于画布，四周留 padding 显露背景。② 背景层（纯色/高斯模糊原图/透明）置于最底层，铺满画布。③ **投影层**：胶片块下方柔和阴影（深色矩形+偏移，经 `sharp.blur()` 软化；librsvg 的 `feGaussianBlur` 在本环境不可靠，故用 sharp blur），使胶片与背景分离。④ 图像层（锐利原图）+ 边框层叠加于投影之上。⑤ `none`+透明背景=纯净抠图，不加投影；其余情况均带投影。
> 9. **布局参数**：默认 `paddingRatio` 由 0 提升至 0.05；padding 最小值强制容纳投影（偏移+模糊半径），避免投影被裁。留白比滑块对所有背景类型可见。
> 10. **中间图像格式**：合成用中间 buffer 统一指定 `.png()`，避免 RAW 输入 `.toBuffer()` 无显式格式时产出不可合成 buffer 的隐患。

> **v1.3.6 修复轮次 8（135/645/66 三层图片边框模型）**：
> 34. **三种画幅真实边框素材**：用户导入 135/645/66 三种画幅真实边框图（`胶片边框/屏幕截图...-135.png` 等），复制至 `resources/film-borders/{135,645,66}.png` 打包。结构分析：每张为「不透明白色照片区 + 不透明齿孔条带 + 透明齿孔/外边距」。白色照片区比例匹配画幅：135=3:2(1.5)、645=4:3 竖(0.74)、66=1:1(1.0)。
> 35. **三层图层模型（核心，自上而下）**：
>     - **图片(top)**：照片以 `fit:'cover'` 裁剪填满边框中间白色照片区（比例不同则放大裁剪，无留缝）。对**原始解码照片**做 cover（不经 step-3 withoutEnlargement），宽幅照片可放大填充。
>     - **边框(mid)**：真实边框图缩放到画布尺寸。不透明部分(齿孔条带+白区)覆盖背景；透明部分(齿孔+外边距)透出下层背景。
>     - **背景(bottom)**：透明/高斯模糊/纯色，铺满画布。透过边框透明处(齿孔+外边距)显出。
>     - 因白色照片区**不透明**，照片必须叠在边框**之上**覆盖白区（区别于旧透明照片区模型）。
> 36. **图片位置与处理**：
>     - 画布尺寸 = 边框图尺寸按目标长边(`config.image.longEdge`/scale/原尺寸)等比缩放。
>     - 白色照片区由 `borderImage.ts` 加载时自动检测(扫描不透明白色像素 bbox)并缓存，缩放到画布坐标得 `white={x,y,w,h}`。
>     - 照片：`img.resize(white.w, white.h, {fit:'cover',position:'center'})` → 置于 `(white.x, white.y)`，作为顶层。
>     - 单次 `composite([{边框},{照片},{边字}])` 按 z 序叠加在背景之上（链式 composite 会丢层）。

## 一、背景与目标

### 1.1 背景

FilmManager 当前已具备完善的胶片扫描文件管理与胶片格式自动识别能力：

- `film_format` 属性体系覆盖 135 / 半格 / 645 / 6×6 / 6×7 / 6×8 / 6×9 / 6×12 / 135 宽幅(Xpan) / 4×5 / 8×10 / 120 通用 等全部主流画幅。
- `detectFilmFormat()`（`src/main/services/thumbnail.ts:482`）已能通过 **齿孔检测 + 120 背纸文字带 + 长宽比** 三级像素分析自动判定画幅；`resolveFilmFormat()`（`src/main/ipc/import.ts:1116`）再结合相机 `camera_formats` 与胶卷 `film_size_type` 约束收敛结果。
- `renderFullPreview()`（`thumbnail.ts:602`）已建立基于 Sharp 的 RAW 解码、ICC 应用、旋转、缩放的成熟渲染管道，并内置 4096px 内存保护与排队丢弃机制。
- `film` 属性携带 `film_size_type`（135/120/both）与品牌 `icon_key`，`camera` 属性携带 `camera_formats` / `camera_default_format`，为边框样式与边字内容提供了结构化数据源。

然而应用目前**没有任何导出能力**：用户无法将管理后的照片带胶片边框输出为成品图，必须借助外部工具（如参考站点 film-index-generator）二次加工，造成数据割裂与体验断层。

### 1.2 目标

新增「带胶片边框导出」功能，对齐参考站点的全部能力，并深度复用本应用已有的胶片格式识别与器材属性数据，实现：

1. **自动匹配**：根据照片的 `film_format` / `film` / `camera` 属性自动选用对应的胶片边框模板（135 齿孔条、120 背纸文字边、Xpan 宽幅齿孔、大画幅净边等）。
2. **手动覆盖**：用户可在导出弹窗中手动切换边框模板、画幅、边框颜色、边字内容。
3. **完整导出配置**：支持 jpg / bmp / png / webp / tiff 格式、画质、分辨率（长边像素 / 缩放倍率 / DPI）、色彩位深（8-bit / 16-bit）、背景类型（透明 / 高斯模糊 / 纯色）、边框颜色、边字。
4. **单张与批量**：支持当前照片单张导出、选中照片批量导出、整卷导出、当前筛选结果导出。
5. **实时预览**：导出弹窗内即时预览边框与边字效果，所见即所得。
6. **配置持久化**：导出预设可保存为命名预设，跨会话复用。

### 1.3 非目标

- 不做图像调色 / 修图（色调、曝光、曲线等交给外部软件，应用已有「用其他应用打开」入口）。
- 不做水印 / Logo 合成（边字系统已可承载品牌文字，不单独引入水印图层）。
- 不做云端导出或在线分享；完全本地。

## 三、总体架构

导出功能遵循应用现有的 **主进程渲染 + IPC + 渲染进程 UI** 三层结构，图像处理全部在主进程通过 Sharp 完成，渲染进程仅负责配置与预览。

```
┌─────────────────────────────────────────────────────────────┐
│ Renderer (React)                                            │
│  ExportModal  ←  触发：PhotoViewer 工具栏 / 照片右键 / 卷菜单  │
│    ├─ 边框模板选择（自动匹配 + 手动下拉）                      │
│    ├─ 边字配置面板                                            │
│    ├─ 导出参数面板（格式/画质/分辨率/位深/背景/边框色）          │
│    ├─ 实时预览 Canvas（缩略图 + 边框 SVG 叠加）                │
│    └─ 目标目录 + 命名模板 + 批量范围                           │
└───────────────┬─────────────────────────────────────────────┘
                │ window.api.export.*  (preload)
┌───────────────▼─────────────────────────────────────────────┐
│ Main Process (IPC handlers)                                 │
│  export:preview   → 渲染小尺寸预览（dataURL）                 │
│  export:render    → 单张渲染并写盘                            │
│  export:batch     → 批量渲染（Worker Pool）                    │
│  export:matchBorder → 返回自动匹配的模板 id 与依据             │
│  export:presets   → 预设 CRUD                                │
│  export:pickDir   → dialog.showSaveDialog / showOpenDialog    │
└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────┐
│ Service Layer (src/main/services/export/)                    │
│  borderTemplates.ts  ← 模板定义（齿孔/背纸/净边/无边）          │
│  borderRenderer.ts   ← SVG 边框 + 边字生成 → Sharp 合成        │
│  exportPipeline.ts   ← 完整管道：解码→背景→边框→文字→编码→写盘  │
│  exportWorker.ts     ← Worker：批量任务执行单元                 │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 为什么用主进程 + Sharp 而非 Canvas

- **格式与位深**：浏览器 Canvas 仅支持 8-bit RGBA，无法产出 16-bit、TIFF、BMP；Sharp/libvips 原生支持。
- **RAW 解码**：复用 `renderFullPreview` 已验证的 RAW + ICC 管道。
- **性能**：批量导出交由 Worker Pool，避免阻塞 UI；Canvas 在渲染进程会卡顿。
- **一致性**：预览与最终输出走同一套 `borderRenderer`，避免「预览对、导出错」。

预览图通过主进程渲染一张 ≤800px 的小图返回 dataURL，渲染进程直接展示；参数变更时防抖（250ms）重渲。

## 四、胶片边框系统设计

### 4.1 模板数据结构

```ts
// src/main/services/export/borderTemplates.ts
export type BorderTemplateId =
  | 'none'
  | '135-sprocket'        // 135 标准齿孔
  | 'half-frame-sprocket' // 半格齿孔（竖向）
  | 'xpan-sprocket'       // 135 宽幅齿孔
  | '120-backing'         // 120 背纸文字边（按画幅参数化）
  | 'large-format-clean'  // 4×5 / 8×10 净边 + 缺角

export interface BorderTemplate {
  id: BorderTemplateId
  label: string                 // 显示名
  applicableFormats: string[]   // 匹配的 film_format 值
  defaultBorderColor: string    // 默认边框色
  // 边框几何（相对图像短边的比例）
  frame: {
    topRatio: number            // 上边框占比
    bottomRatio: number
    leftRatio: number
    rightRatio: number
    sprocket?: {                // 齿孔参数（135 系列）
      rows: number              // 上下各几排
      holeCount: number         // 每排齿孔数
      holeWidthRatio: number    // 单孔宽 / 边框宽
      holeHeightRatio: number
      holeGapRatio: number
    }
    notch?: boolean             // 大画幅缺角
  }
  // 边字默认排版
  edgeText: {
    defaultPositions: ('top' | 'bottom' | 'left' | 'right')[]
    defaultTokens: string[]     // 默认边字 token，如 ['film','iso','date']
  }
}
```

### 4.2 模板与画幅映射

复用现有 `CAMERA_FORMAT_TOKEN_MAP`（`import.ts:1051`）与 `film_format` 预设值，建立映射表：

| `film_format` 属性值 | 边框模板 | 说明 |
|---|---|---|
| `135 / 35mm` | `135-sprocket` | 上下齿孔条 |
| `半格 / 17.5mm` | `half-frame-sprocket` | 左右齿孔条（竖向单帧） |
| `135 宽幅 / Xpan` | `xpan-sprocket` | 上下齿孔条，帧加倍宽 |
| `645 中画幅` / `6x6 中画幅` / `6x7 中画幅` / `6x8 中画幅` / `6x9 中画幅` / `6x12 中画幅` / `120 中画幅` | `120-backing` | 背纸文字边，按画幅调整边框比例与品牌文字 |
| `4x5 大画幅` / `8x10 大画幅` | `large-format-clean` | 净边 + 缺角 |
| 未识别 / 无 | `135-sprocket`（默认）或 `none` | 用户可手动切换 |

> **120 系列统一模板**：不同 120 画幅共用 `120-backing` 模板，差异通过 `frame` 比例与边字帧号密度参数化（6×6 帧号居中，6×7 帧号偏移等），避免模板爆炸。

### 4.3 边框渲染（SVG + Sharp 合成）

边框（齿孔、纯色边、缺角）与边字统一用 **SVG** 绘制，再通过 `sharp.composite()` 叠加到图像上。libvips 内置 librsvg，支持 SVG 矢量输入与 `<text>`，可保证任意分辨率下齿孔与文字清晰、无锯齿。

```ts
// src/main/services/export/borderRenderer.ts
import sharp from 'sharp'

/**
 * 生成与目标画布等尺寸的 SVG 覆盖层（边框 + 边字）。
 * 返回可直接 composite 的 SVG Buffer。
 */
export function buildBorderOverlay(opts: {
  canvasWidth: number
  canvasHeight: number
  template: BorderTemplate
  borderColor: string
  edgeText: EdgeTextConfig
  tokens: Record<string, string>   // 已解析的边字 token 值
}): Buffer {
  const svg = renderBorderSvg(opts)   // 拼装 <rect>/<circle>/<text>
  return Buffer.from(svg, 'utf-8')
}
```

**135 齿孔绘制要点**：
- 边框为整块纯色 `<rect>` 覆盖上下两条（`topRatio` / `bottomRatio`）。
- 齿孔为透空圆角矩形 `<rect rx>`，等距排列；孔数随画布宽度自适应（`holeCount` 基准 + 按 `canvasWidth / 短边` 缩放），避免宽幅下齿孔过疏。
- 边字以 `<text>` 绘制在齿孔条上方/下方的净边区，左右两端各一组（模拟胶片边缘的 brand + frame number 双侧印刷）。

**120 背纸文字边要点**：
- 边框为纯色 `<rect>`，宽度按画幅比例（6×6 上下左右等宽，6×7 上下窄左右宽以保留背纸帧号区）。
- 品牌文字按 `film` 属性的 `icon_key` / 品牌映射为大写红/黑字（KODAK 红、FUJI 绿、ILFORD 黑、Kodak 黄），可被边框颜色配置覆盖。
- 帧号沿边框单边等距递增打印（`{frame_no}`），模拟背纸印刷。

**大画幅净边 + 缺角**：
- 纯色等宽边框，右上角切一个三角形缺口（notch）作为方向指示，用 SVG `<path>` 绘制。

### 4.4 边字（edge text）系统

```ts
export interface EdgeTextConfig {
  enabled: boolean
  positions: ('top' | 'bottom' | 'left' | 'right')[]
  // 每个 position 一组独立内容（用 ';' 分隔多行）
  content: Record<string, string>   // 如 { top: '{film} · {iso}', bottom: '{date} | {frame_no}' }
  font: string                      // 字体族（系统字体，见 §4.5）
  fontSizeRatio: number             // 字号 / 边框宽度
  color: string
  opacity: number                   // 0–1
  align: 'left' | 'center' | 'right'
  letterSpacing: number
}
```

**支持的 token**（值在主进程从 DB + EXIF 解析后传入）：

| Token | 来源 |
|---|---|
| `{film}` | `film` 属性 value |
| `{camera}` | `camera` 属性 value |
| `{lens}` | `lens` 属性 value |
| `{format}` | `film_format` 属性 value |
| `{date}` | `shot_date`（按 `YYYY.MM.DD`） |
| `{iso}` / `{aperture}` / `{shutter}` / `{focal}` | EXIF（`getExifData`） |
| `{frame_no}` | 批量导出递增编号（可配起始/步长/前缀/位数） |
| `{roll}` | 所属卷 name |
| `{location}` | `photo_locations` 关联地点 name |
| `{custom}` | 用户自定义静态文本 |
| `{original}` | 原始文件名（不含扩展名） |

**帧号规则**：批量导出时主进程维护计数器，`{frame_no}` 支持 `start`、`step`、`digits`、`prefix`（如 `#01A`）。单张导出时取照片在卷内的序号或固定 `01`。

### 4.5 字体策略

SVG `<text>` 渲染依赖系统字体。为保证中文边字（胶片名、地点）可用：

- **优先级**：Windows 下使用 `Microsoft YaHei` / `Segoe UI`；中英混排时 fallback 到 `Arial`。
- **字体文件内嵌（可选增强）**：将一套开源中文字体（如思源黑体子集）放入 `resources/fonts/`，通过 `extraResources` 打包，渲染时用 `@font-face` 内嵌 base64 注入 SVG。**首期采用系统字体**，内嵌字体列为后续优化。
- 渲染进程的字体下拉仅列出主进程通过 `export:listFonts` 返回的可用字体（过滤中文字体）。

### 5.1 自动匹配流程

```ts
// src/main/services/export/exportPipeline.ts
async function resolveBorderForPhoto(photoId: number): Promise<{
  templateId: BorderTemplateId
  filmFormat: string | null
  source: 'attr' | 'detect' | 'default'
}> {
  // 1. 优先读已存的 film_format 属性
  const fmt = getPhotoAttr(photoId, 'film_format')
  if (fmt) return { templateId: mapFormatToTemplate(fmt), filmFormat: fmt, source: 'attr' }

  // 2. 无属性则现场检测：复用 resolveFilmFormat（需 film_size_type + camera_formats）
  const photo = getPhoto(photoId)
  const filmSizeType = getFilmSizeType(photoId)            // 复用 import.ts:1041 逻辑
  const cameraInfo = getPhotoCameraFormatInfo(photoId)      // 复用 import.ts:1069
  const detected = await resolveFilmFormat(                 // 复用 import.ts:1116
    photo.file_path, photo.width, photo.height, filmSizeType, cameraInfo
  )
  if (detected) return { templateId: mapFormatToTemplate(detected), filmFormat: detected, source: 'detect' }

  // 3. 仍无结果 → 默认 135 齿孔
  return { templateId: '135-sprocket', filmFormat: null, source: 'default' }
}
```

> **关键**：`resolveFilmFormat` / `getPhotoCameraFormatInfo` 当前为 `import.ts` 内私有函数。本方案将其**抽取到 `src/main/services/film-format.ts`** 共享模块，导入与导出共用，避免逻辑分叉。

### 6.2 格式能力矩阵与降级规则

| 格式 | 透明 | 16-bit | 画质 | 适用场景 |
|---|---|---|---|---|
| JPEG | ✗（自动降级纯色 + 提示） | ✗ | 1–100 | 社交分享 |

| WebP | ✓ | ✓ | 1–100 | 高压缩归档 |

### 6.3 色彩位深与色彩空间

- **8-bit**：所有格式默认。Sharp `png({ depth: 'uchar' })` / `jpeg` / `webp`。
- **16-bit**：仅 PNG/WebP/TIFF。Sharp 需在管道中 `.toColourspace('rgb16')` 或保留 16-bit 输入：对 RAW 输入保留 16-bit，对 8-bit 原图升位无意义（仅扩容），UI 提示「原图为 8-bit，16-bit 仅扩容不增信息」。
- **色彩空间**：`srgb` 调用 `.toColorspace('srgb')` 并嵌入 sRGB ICC；`preserve` 保留原图 ICC（`withMetadata({ icc })`）。

## 七、渲染管道

### 7.1 单张导出管道

```ts
// src/main/services/export/exportPipeline.ts
export async function renderExport(
  photoId: number,
  config: ExportConfig,
  frameNo: number,
  outPath: string
): Promise<{ width: number; height: number; bytes: number }> {
  const photo = getPhoto(photoId)

  // ── 1. 解码原图（复用 RAW + ICC 管道，但不做 4096 限制） ──
  const decoded = await decodeForExport(photo.file_path, photo.rotation)
  let img = decoded.pipeline                  // sharp.Sharp
  const meta = decoded.meta                   // { width, height, hasAlpha, icc }

  // ── 2. 色彩空间 ──
  if (config.image.colorSpace === 'srgb') img = img.toColorspace('srgb')

  // ── 3. 分辨率缩放 ──
  const targetSize = resolveTargetSize(meta, config.image)
  if (targetSize) img = img.resize(targetSize.w, targetSize.h, { fit: 'inside', withoutEnlargement: !config.image.scale })

  // ── 4. 计算画布尺寸（图像 + 边框 + 背景留白） ──
  const { canvasW, canvasH, imgX, imgY, imgW, imgH } = computeLayout(meta, config)

  // ── 5. 背景层 ──
  let canvas: sharp.Sharp
  if (config.background.type === 'transparent') {
    canvas = sharp({ create: { width: canvasW, height: canvasH, channels: 4, background: { r:0,g:0,b:0,alpha:0 } } })
  } else if (config.background.type === 'solid') {
    canvas = sharp({ create: { width: canvasW, height: canvasH, channels: 4, background: hexToRgba(config.background.color) } })
  } else {
    // 高斯模糊：原图重采样放大到画布尺寸 + 强模糊
    const blurred = await img.clone().resize(canvasW, canvasH, { fit: 'cover' })
      .blur(config.background.blurSigma).toBuffer()
    canvas = sharp(blurred)
  }

  // ── 6. 图像缩放到帧内尺寸并合成到画布 ──
  const imgBuffer = await img.resize(imgW, imgH, { fit: 'inside' })
    [config.image.depth === 16 ? 'toColourspace' : 'toColourspace']('srgb')
    .toBuffer()
  canvas = canvas.composite([{ input: imgBuffer, left: imgX, top: imgY }])

  // ── 7. 边框 + 边字 SVG 覆盖层 ──
  const tokens = await resolveTokens(photoId, frameNo, config)
  const overlay = buildBorderOverlay({
    canvasWidth: canvasW, canvasHeight: canvasH,
    template: getTemplate(config.border.templateId),
    borderColor: config.border.borderColor,
    edgeText: config.edgeText,
    tokens
  })
  canvas = canvas.composite([{ input: overlay, left: 0, top: 0 }])

  // ── 8. 编码输出 ──
  const encoded = await encode(canvas, config.image, meta)
  await fs.promises.writeFile(outPath, encoded.buffer)
  // ── 9. DPI / ICC 元数据（PNG pHYs / TIFF 分辨率） ──
  await writeResolutionMetadata(outPath, config.image.dpi, config.image.format)

  return { width: canvasW, height: canvasH, bytes: encoded.buffer.length }
}
```

### 7.2 编码细节

```ts
function encode(canvas: sharp.Sharp, img: ImageConfig, meta: DecodedMeta) {
  const opts: sharp.OutputOptions = {}
  switch (img.format) {
    case 'jpeg': return canvas.jpeg({ quality: img.quality, chromaSubsampling: '4:2:0' }).toBuffer({ resolveWithObject: true })
    case 'webp': return canvas.webp({ quality: img.quality, lossless: img.depth === 16 }).toBuffer({ resolveWithObject: true })
    case 'png':  return canvas.png({ quality: img.quality, compressionLevel: 6,
                    palette: false, colours: img.depth === 16 ? 65536 : 256 }).toBuffer({ resolveWithObject: true })
    case 'bmp':  return canvas.toFormat('bmp').toBuffer({ resolveWithObject: true })
    case 'tiff': return canvas.tiff({ quality: img.quality, bitdepth: img.depth === 16 ? 16 : 8 }).toBuffer({ resolveWithObject: true })
  }
}
```

> **Sharp 16-bit**：libvips 对 PNG/TIFF/WebP 支持 16-bit。需在 `toBuffer` 前确保管道为 16-bit 色彩空间（`toColourspace('rgb16')`），否则降级 8-bit 且不报错。测试用例需校验输出位深。

### 7.3 内存保护

- 单张长边硬上限 **8000px**（防止 16-bit 大画幅 OOM），超出自动降采样并提示。
- 批量导出通过 Worker Pool（复用 `worker-pool.ts`）限流，默认并发 = CPU 核数 - 2（与缩略图生成一致）。
- 渲染过程中主进程向渲染进程推送 `export:progress`（已处理 / 总数 / 当前文件名 / 成功 / 失败）。

## 十一、文件命名与批量导出

### 11.1 命名模板

支持的 token：`{original}` `{film}` `{camera}` `{date}` `{frame_no}` `{frame_no_padded}` `{roll}` `{index}` `{format}`。

- `frame_no`：按 `frameNo` 配置递增（`#01`、`#02`…）。
- `frame_no_padded`：固定位数补零（`0001`）。
- `index`：批量序号（1-based），与帧号独立。
- 非法文件名字符（`\/:*?"<>|`）自动替换为 `_`。
- 同名冲突按 `output.overwrite` 策略：`skip` 跳过、`overwrite` 覆盖、`rename` 追加 `_2`。

### 11.2 批量执行

- 主进程 `createExportTaskQueue` 将 `photoIds` 映射为 `[{ photoId, frameNo, outPath }]`。
- 复用 `src/main/workers/worker-pool.ts`，新增 `exportWorker.ts`（仿 `thumbnail-worker.ts`，子线程内 `require('sharp')` 执行单张渲染，避免主线程阻塞）。
- 进度事件节流 100ms，避免高频 IPC 风暴。

## 十三、风险与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| 16-bit PNG/TIFF 在某些看图软件显示异常 | 输出看似发暗 | UI 标注「16-bit 需专业软件查看」；默认 8-bit |
| JPEG 不支持透明/16-bit | 配置冲突 | UI 即时降级 + 提示，不允许导出非法组合 |
| SVG `<text>` 中文字体在打包环境缺失 | 边字方块 | 系统字体兜底 + 后续内嵌字体子集 |
| 大尺寸 16-bit 导出 OOM | 进程崩溃 | 长边硬上限 8000px + Worker 隔离 + 内存监控 |
| 批量导出中途取消 | 部分文件已写 | 取消仅停止后续任务，已写文件保留并汇总报告 |
| RAW 解码依赖 Sharp/libvips 版本 | 部分 RAW 不可导出 | 复用 `renderFullPreview` 的 RAW 回退（嵌入 JPEG）逻辑 |
| 边框比例在不同长宽比下失真 | 齿孔疏密不均 | 齿孔数按画布宽度自适应，单元测试覆盖 1:1 / 3:2 / 16:9 / Xpan |
| 高斯模糊背景对纯色边缘图效果差 | 视觉空洞 | 当图像短边占比 > 90% 时自动建议切纯色背景 |

### 13.1 安全边界

- `output.dir` 必须为用户显式选择（`dialog`），不接受渲染进程任意路径写盘。
- 写盘前校验路径可写、磁盘剩余空间（预估 = 单张体积 × 数量 × 1.2）。
- 复用 `photos:thumbDataUrl` 的路径越界校验思路：导出目录不限定在 libraryRoot 内，但禁止写入系统关键目录（通过黑名单 + `app.getPath` 比对）。
