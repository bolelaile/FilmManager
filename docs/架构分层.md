# FilmManager 架构分层

> 渐进式分层重构后的项目架构。目标：功能模块独立封装、层间调用清晰、便于单独升级或替换。

## 分层总览（6 层，单向依赖）

```
┌─────────────────────────────────────────────────────────────┐
│ 6. UI 层            renderer/components                      │  React 组件，仅依赖 store/hooks/service-client
├─────────────────────────────────────────────────────────────┤
│ 5. 应用协调层       renderer/app + main/app                  │  页面协调、状态编排、Electron 窗口/生命周期、DI 装配
├─────────────────────────────────────────────────────────────┤
│ 4. 服务接口层       shared/services + main/ipc-adapters      │  统一 Service 接口契约 + IPC 薄适配
├─────────────────────────────────────────────────────────────┤
│ 3. 功能核心层       main/features/*                          │  独立功能封装，依赖 Repository/工具，无 Electron/DB 直连
├─────────────────────────────────────────────────────────────┤
│ 2. 数据访问层       main/data (Repository)                   │  封装所有 SQL，暴露领域模型与接口
├─────────────────────────────────────────────────────────────┤
│ 1. 基础设施层       main/infra + shared                      │  DB 连接、配置、日志、IPC 总线、Worker Pool、图像工具
└─────────────────────────────────────────────────────────────┘
```

**依赖规则**：上层单向依赖下层；功能核心不直接 `getDb()`/`ipcMain`；IPC 适配层仅参数转换+调用核心+返回；UI 层经 service-client 调用，不直接 `ipcRenderer`。

## 各层说明

### 1. 基础设施层 `main/infra/` + `shared/`
- `infra/image-utils.ts`：纯图像工具（isRawFormat/normalizeRotation/computeContentHash/extractEmbeddedJpeg/decodeBmp）
- `infra/config.ts`：库根目录配置读写
- `infra/ipc-bus.ts`：IPC handle/send 统一封装
- `shared/`：跨进程类型（import-types/export-types/services 接口契约）

### 2. 数据访问层 `main/data/`
- `data/repositories/`：7 个 Repository（Photo/SubLibrary/Attribute/Roll/Location/ExportPreset/ImportQueue）
- `data/types.ts`：Repository 行类型 + QueryFilter/Paging
- `data/index.ts`：createRepositories 工厂
- 全部 SQL 集中于此；功能核心与 IPC 不写 SQL

### 3. 功能核心层 `main/features/`
每个功能一个目录，对外暴露 Service，内部可分子模块：

| 功能 | Service | 子模块 |
|---|---|---|
| photos | PhotoService | — (COUNT 缓存/全屏预览单飞) |
| import | ImportService | folder-scanner / equipment-resolver / gps-linker / sublibrary-resolver |
| rolls | RollService | — |
| attributes | AttributeService | — (faceted/图标/别名/JSON 导入) |
| sublibrary | SubLibraryService | — (委托 library-layout) |
| locations | LocationService | osm-geocoder |
| library | LibraryService | — (ICC/统计/缩略图重生成) |
| export | ExportService | exportPipeline / film-frame-renderer / stock-presets |
| thumbnails | (thumbnail.ts 工具) | — |
| film-format | (film-format.ts) | — (导入/导出共享) |
| library-layout | (library-layout.ts) | — (磁盘目录树同步) |
| external-apps | ExternalAppService | — (检测/打开) |

### 4. 服务接口层 `shared/services/` + `main/ipc/`
- `shared/services/`：Service 接口契约（IPhotoService 等，主/渲染共享类型）
- `main/ipc/`：9 个薄 adapter（仅注册 IPC + 转发到 Service，无 SQL/业务逻辑）

### 5. 应用协调层
- `main/app/bootstrap.ts`：DI 装配（统一构造 Repository + Service 单例）
- `main/index.ts`：Electron 窗口/协议/生命周期
- `renderer/src/pages/Library.tsx`：页面协调 + 状态编排

### 6. UI 层 `renderer/components/` + `renderer/services/`
- `renderer/services/service-client.ts`：window.api 类型化封装（UI 经此调用）
- `renderer/store/`：Zustand 三 slice（filter/library/ui）
- `renderer/hooks/`：usePhotoLoader/useRollLoader/useLibraryData

## 调用链

```
UI 组件 → service-client → window.api(preload) → ipc-adapters → features Service → data Repository → DB
                                                                          ↓
                                                              infra/图像工具 + workers
```

## 重构批次记录
- 批次0：分层骨架 + infra 抽取 + 功能测试流程
- 批次1：Repository 数据层（7 个 Repository）
- 批次2：功能核心层（9 个 Service + IPC 薄 adapter）
- 批次3：services 归位 features，统一功能核心层
- 批次4：渲染层 service-client
- 批次5：DI 装配 + 文档收尾
